# 本轮实际结果

持续目标未完成；本轮补齐监听和原因证据，没有启用新的提速方案。

实测同一视频2条，每条录25秒。另有1次点击前脚本参数错误，未播放，不计有效样本。

| 样本 | 点击到真实媒体图像 | 点击到确认动态画面 | 监听结果 |
| --- | ---: | ---: | --- |
| d1r | 4.671秒 | 4.739秒 | Dart采样成功；时间线开头被覆盖，原生离开CPU采样失败 |
| d2 | 5.056秒 | 5.089秒 | 实时时间线61045事件、8个API区间、2242个Dart样本、1790个原生样本 |

画面时间由原始WebM逐帧核对；视频封面和转圈不算。边界附近帧间隔约33–35毫秒。
两条起播后未记录再次缓冲或暂停；第二条后续抽帧有运动，尚不能据此保证全程流畅。

这些是带采样和详细监听的诊断包结果，不改写旧版2.45秒release样本的口径。
监听存在开销：421/1790原生样本涉及诊断类或采样线程，Dart时间线写入也占明显样本；
Flutter的profile构建在Android上继承debuggable=true。不能把这些差异忽略后直接比较秒数。

第二条已确认的分段：

- 主接口函数约1129毫秒。playurl传输适配器约718毫秒，其中响应头交付前约685毫秒；这不等于已经分清DNS、连接、TLS和服务器时间。
- 真实媒体提交打开到原生解码器Init开始约1230毫秒；仍包含连接、读取、识别及调度，原生媒体首字节未精确捕获。
- 原生解码器Init、configure、start调用区间合计约327毫秒。
- flush后首次客户端输入到首次Surface提交约875毫秒。期间HEVC服务调度运行约697毫秒，客户端也有睡眠和就绪等待。这些会并行，不能相加成总等待。
- Surface提交之后到真正可见图像，还涉及纹理消费、Flutter、系统合成和模拟器显示/录屏，目前没有把这部分全部分开。

模拟器内存压力确实参与了这条记录：主接口开始后5.5秒内，kswapd被调度运行约3257毫秒，
同时有换页、解码服务和其他进程内存增长。不能只归因于App，也不能据此宣称旧2.45秒样本原因相同。
主机内存门槛始终通过，两条录制最低可用物理内存分别7.736和7.135GiB。

下一步先降低重复观测的开销，保留函数、异步和调度覆盖；核对同条件release基线和真正显示前的等待。
在主要耗时没有明确前，不继续叠加提速候选。
