# 第一项保留，继续叠加

同一轮 AVD、1080p HEVC、轻监听，真实应用内搜索提交，均先 force-stop 应用。输入到首个正时间戳且变化的纹理消费（不是物理显示完成）如下：

| 方案 | 样本 | 时间 ms | API ms | source.open 到纹理 ms |
| --- | --- | ---: | ---: | ---: |
| 原方案 | control-03 | 1812.8 | 225.4 | 1463.1 |
| 音频提前 | candidate-01 | 1513.7 | 210.0 | 1138.3 |
| 音频提前 | candidate-02 | 1453.8 | 274.2 | 1069.4 |
| 原方案 | control-04 | 1989.1 | 234.4 | 1589.9 |
| 原方案 | control-05 | 1757.5 | 248.8 | 1402.8 |
| 音频提前 | candidate-03-return | 1371.7 | 233.8 | 1032.2 |

中位数 1812.8 → 1453.8 ms，减少约 359 ms（19.8%）。API 中位数基本相同（234.4 与 233.8 ms）；source.open 后中位数减少约 394 ms。小样本、单视频，不能外推所有网络/视频，更未达到 0.8 秒。control-02 为开机/安装后的准备样本，期间额外读取 UI，单独保留，其 3109 ms 不纳入上述对照；control-01 设备启动后包查询失败，无有效采集。

音频 headers 在 mpv 请求本地音轨前到达，未走 fallback。candidate-01/02 各观察 25 秒（纹理监听窗口约 20 秒），无起播后的再次 buffering；起播后没有记录到 >=100 ms 的纹理回调间隔。AudioFlinger 中目标 PID 有活跃音轨、Underruns=0。现有正时间戳边界会跳过 PTS=0，仍不能单独确认物理显示或逐帧媒体来源。

candidate-03-return 播放 10 秒后返回，音频 closed 记录及最终无活跃音轨；AVD 保持在线。candidate-04-cancel 在 0.668 秒发出返回，音频随后关闭、没有残留活跃音轨。取消样本没有正时间戳纹理，采集器因此退出 1，这是此用例预期，不作为性能失败；delivery.error 出现在退出关闭阶段，需与正常播放错误分开。传输与播放队列共 16 项测试通过。

下一步：保留音频提前，构建 combined.apk 额外启用已有 SOURCE_EARLY_PREPARE，验证页面挂载与媒体打开重叠的增量收益及取消安全。当前候选编译开关仍默认 false，暂不宣称普遍上线验收。
